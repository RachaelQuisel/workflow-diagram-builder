# How-it-works guide

Read the current source and the confirmed answers before writing the guide. Use a title followed by exactly these four sections.

## Trigger

- State the event that starts the workflow.
- State every condition that must be true before it starts.

## Inputs

- List every piece of information the workflow reads or receives.
- Name each source. Explain the purpose when it is unclear.

## What happens

1. List every action in order.
2. Name the actor in each action.
3. State each condition before its result.
4. Include alternate routes, stopping points, failures, and retries that the source contains.

## Outputs

- List everything the workflow creates, changes, sends, or records.
- Name the destination for each output.

Use complete sentences and common words. Keep each fact in one place. Preserve exact names. Avoid analogies, filler, em dashes, and a closing summary. Label a required missing fact as unknown.

When saving is requested, use the project's existing naming convention. Save the guide beside the relevant source when that folder exists. Update an existing running-updates-and-questions.md only when it belongs to the selected project. Record the current state accurately. A saved guide is documentation of the source inspected for that run.
